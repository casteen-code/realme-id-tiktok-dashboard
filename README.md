## 库存周转管理

双击打开 `inventory-turnover.html` 即可使用，无需安装软件或上传数据。

1. 上传马卡萨、坤甸、巴厘岛三个 WMS 库存文件，以及 Shopee、TikTok 上周销量文件。
2. 在“导入预览与数据对账”确认工作表、字段和控制数。支持 Shopee 的 `SKU + 1店至5店 + 合计` 横向表，也支持 `SKU + 店铺 + 销量` 明细表。横向表只累计各店销量，排除合计行、合计列，预览会显示分店控制数。
   赠品编码 `zp888`（不区分大小写和首尾空格）从库存、销量、匹配和周转计算中排除，预览会列出排除数量，无需补全 SKU。其他商品仍检查型号、内存和颜色。
3. 如果 Shopee 的“分组明细”和“透视表”不一致，先明确选择采用哪个来源，再计算。
4. 先在“库存 SKU 识别自检”补全未识别的库存 SKU，再在“销售 SKU 待确认”中手动保存不确定的对应关系；规则只保存在本机，可备份为 JSON。

页面右上角会显示版本号，当前为 `v3.4.2`。在线页面显示旧版本时，请强制刷新，再重新上传本周文件计算。旧历史快照保留当时的结果，不会自动重算。

仓库归属：Shopee 1店、3店和 TikTok 归巴厘岛；4店归坤甸；2店、5店归马卡萨。

计算公式：`周转天数 = 可用库存 ÷（周销量 ÷ 7）`。

结果表按 W33 口径展示：可用库存、Shopee 1–5 店和 TikTok 的销量、周销量、日均销量、周转天数和匹配状态。仓库仅用于筛选，不在结果表重复展示库存拆分。

仓库筛选映射固定为：巴厘岛仓 = 1店 + 3店 + TikTok；坤甸仓 = 4店；马卡萨仓 = 2店 + 5店。

## 数据安全

- 所有 Excel 文件仅在当前浏览器中读取，不会上传。
- 历史记录仅保存计算结果和对账信息，不保存原始 Excel。
- 仓库中不提交订单、销量、SKU 或客户原始数据。

## SKU 识别保障

- 识别、匹配和库存自检共用 `sku-core.js` 这一套规则，避免页面和修复脚本各自判断。
- `tests/sku-regression.js` 会检查库存写法与销量写法是否统一到同一 SKU，并确保 `16`、`16 Pro`、`16 Pro+` 不会混为一款。
- 每次更新 SKU 规则前运行 `node tests/sku-regression.js`；GitHub 也会自动执行该检查。
- 该命令同时检查横向表与明细表导入、合计和赠品排除、各店仓库归属、零销量以及多工作表来源选择。测试仅使用虚构数据。

## 活动背景工坊 · Campaign Motion Studio

在线打开：[活动背景编辑器](https://casteen-code.github.io/realme-id-tiktok-dashboard/campaign-motion-studio/)

编辑器源码、独立素材、使用说明和检查脚本位于 [`campaign-motion-studio/`](campaign-motion-studio/)。支持更换活动图片、抠图、独立旋转与动效、手机间距、固定预览、图层排序和视频导出。图片及项目在当前浏览器中处理；请使用“保存项目”或“保存独立 HTML”保留自己的活动。

开发：在 `campaign-motion-studio/` 目录运行 `npm ci`、`npm test`、`npm run build`，将源码和重新生成的 `index.html` 一起提交。现有 Pages 从 `main` 根目录发布，编辑器作为子目录页面提供。
